# 群面实验室 GroupLab

> 与三名不同风格的 AI 候选人完成一场无领导小组讨论，并获得基于团队状态变化的影响力报告。

普通模拟面试通常只评价“你答得怎么样”。群面实验室关注另一个问题：**你的发言有没有让团队向前走？**

当前版本提供内置与岗位定制题库、三档对抗难度，以及“实时大模型导演 + 确定性状态机兜底”的混合训练系统。配置 API Key 后，用户可以根据岗位、行业和公司类型生成专属群面题，三名 AI 候选人会依据当前案例、难度和完整讨论动态回应；接口暂时不可用时，训练环节会自动切回可复现的演示导演。

## 当前核心闭环

1. 从内置题库选择案例，或输入岗位、行业和公司类型生成专属群面题。
2. 选择入门陪练、真实群面或高压挑战难度。
3. 阅读案例方案，通过语音或文字与三名固定行为风格、不同初始立场的 AI 候选人讨论。
4. 群体状态机识别用户的协作动作。
5. 共享面板实时更新评价标准、候选方案、核心冲突和共识度。
6. 用户代表小组完成最终陈述。
7. AI 为每轮提取用户原话证据、团队影响和可执行改进动作。
8. AI 回答可由浏览器朗读；语音发言会记录时长、语速与明显停顿。
9. 系统生成五维评分、表达节奏、证据化影响时间线和下一轮唯一训练目标。
10. 系统从可恢复轮次中推荐最需要改进的一轮，用户可在完全相同的讨论现场连续重练三次。
11. 每次重练都会按回应整合、结论优先级、数据与限制、行动与验证、简洁清楚五项稳定规则评分，AI 团队影响作为补充证据，并自动解释最佳版本。
12. 报告和专项重练结果自动保存到当前浏览器，成长档案展示多场训练趋势。

## 本轮修复

- 现在只说“结合、总结、时间”等词不会再自动获得协作意图或共识加分，动作必须落到案例中的具体标准、方案、限制或真实分歧。
- 用户没有提到评价维度或方案别名时，共享面板不会再补入默认标准或默认候选方案。
- 模型给出的 evidence 必须能锚定用户原话，完全对不上时整份 assessment 会回退到确定性规则，模型的高共识增量也会被丢弃。
- 共识条现在表示用户发言对团队标准、候选方案和未解冲突造成的可证实推进，允许显示正增量、零增量和负增量，而不是发言流畅度或关键词命中率。
- 高压模式会保留尚未被回应的候选人反对，用户没有处理该立场时不能让共识继续上涨。
- 专项重练评分会读取当时的冲突、候选方案和最后两条 AI 发言，只有回应现场主张、采用真实方案与案例数字、并给出对应验证动作才会得到高分。
- 讨论中的最新影响会同时显示用户原话、共识变化和未推动原因，便于在三十秒演示中直接看出它不是普通聊天机器人。
- 高压模式下只要上一轮候选人的具体反对尚未被回应，引擎就会把本轮共识增量锁定为零或负数，而不再依赖导演是否遵守提示词。
- 只堆“不同意、风险、预算”等单词不会被识别为有效 challenge，质疑必须落到当前冲突、候选人原话或至少两个案例实体。
- 最终陈述不再默填预设方案，只保留用户原话中真正点到且通过 grounding 的方案，因此未收敛会被如实呈现。
- 高压模式判定本轮未推动时，候选人会点名并追问尚未处理的反对，而不会一边锁住共识条一边祝贺讨论已经推进。
- 冲突面板只接受能锚定用户原话或上一轮候选人发言的具体分歧，不再被“兼顾两种主张”等万能套话覆盖。
- 最终陈述会保留讨论阶段已经由用户点名的候选方案，同时仍不会用预设 fallback 方案补足数量。

## 岗位定制题库

题库页可以调用当前已配置的大模型生成专属案例。生成结果包含业务背景、限制条件、关键事实、五个候选方案、三名候选人的不同初始立场和岗位相关评分维度。用户可以先修改标题、背景、目标、限制条件及方案内容，再保存到当前浏览器或直接开始训练。

生成案例中的公司、数据和事件均为虚构内容，只用于面试训练，不应当作真实企业资料。

## 混合导演架构

系统使用一个统一的“群面导演”协调三名候选人，而不是让三个对话请求互相争抢上下文：

- 兼容 OpenAI 格式的模型接口根据所选案例、难度、团队状态和历史对话生成动态回应；
- 入门模式偏向建设性追问，标准模式保留真实分歧，高压模式会严格挑战证据与限制条件；
- JSON Mode 与 Zod 校验保证候选人和发言结构可被前端稳定消费；
- AI 识别建立标准、整合分歧、冲突处理和推动进展等协作行为；
- 本地状态机负责分数限幅、事实过滤、共识度、共享面板与兜底证据；
- 最终陈述单独检查标准、两个方案、核心理由与风险控制；
- 模型失败、超时或未配置密钥时自动使用确定性回应；
- API Key 只存在于服务端环境变量，不发送到浏览器。

## 评分维度

| 维度 | 分值 | 观察内容 |
| --- | ---: | --- |
| 有效贡献 | 25 | 是否提出新信息、判断标准或明确方案 |
| 推动进展 | 25 | 是否帮助团队从发散走向结论 |
| 倾听整合 | 20 | 是否回应并吸收他人的有效观点 |
| 冲突处理 | 15 | 是否让分歧产生信息，而不是变成人际对抗 |
| 结构节奏 | 15 | 是否建立标准、控制时间并清楚总结 |

## 本地运行

环境要求：Node.js 20.9 或更高版本。

```bash
npm install
npm run dev
```

打开 [http://localhost:3000](http://localhost:3000)。

语音功能不需要额外 API。使用时允许浏览器访问麦克风；如果当前浏览器不支持语音识别，文字训练仍可正常使用。

### 启用实时 AI（推荐：阿里云百炼）

复制环境变量示例：

```powershell
Copy-Item .env.example .env.local
```

然后在 `.env.local` 中填写：

```dotenv
AI_PROVIDER=bailian
AI_API_KEY=你的百炼_API_Key
AI_BASE_URL=https://dashscope.aliyuncs.com/compatible-mode/v1
AI_MODEL=qwen-flash
```

重新运行 `npm run dev`。页面右上角显示“实时 AI”即代表接入成功。不要把真实密钥提交到 GitHub，也不要粘贴到前端代码中。

也可以将 `AI_PROVIDER`、`AI_BASE_URL` 和 `AI_MODEL` 改为 DeepSeek、OpenAI 或其他兼容接口；旧的 `OPENAI_API_KEY` 与 `OPENAI_MODEL` 配置仍然兼容。

## 项目结构

```text
src/
  app/                 页面入口与全局样式
    api/director/      服务端大模型导演接口
    api/scenario-generator/ 服务端岗位题目生成接口
  components/          题库生成、群面流程、成长档案、讨论房间与报告 UI
  lib/
    director.ts        多模型兼容层、候选人导演与证据化评分提示词
    scenario.ts        三类案例、难度、方案和候选人设定
    engine.ts          意图识别与群体状态机
    history.ts         本地训练记录、容错读取与趋势数据
    custom-scenarios.ts 自定义题库的本地保存与容错读取
    scenario-schema.ts 场景输入和生成结果校验
    retrain.ts         关键轮次新旧表现对比
    scoring.ts         五维报告与表达节奏生成
    voice.ts           语速、时长和停顿分析
  hooks/
    use-browser-voice.ts 浏览器语音识别与回答朗读
    *.test.ts          状态机与训练记录测试
    types.ts           领域类型
```

## 当前取舍

刻意没有加入：

- 视频和数字人；
- 登录、简历和跨设备云端同步；
- 三个相互独立且不可控的 Agent；
- 只根据发言次数生成的笼统评分。

第一阶段优先验证一个问题：学生是否能从“团队状态变化”反馈中获得比普通聊天式模拟更有价值的群面训练。

## 下一步

- 增加真实群面录像标注集，校准评分一致性；
- 根据真人试用结果校准语速区间和停顿阈值；
- 根据真人试用结果调整连续重练的推荐逻辑和最佳表现判定；

## 隐私

当前案例不要求上传简历或真实个人信息。测试和演示请继续使用假名与脱敏数据。训练记录和自定义题目保存在当前浏览器的本地存储中，清除该站点的浏览器数据即可删除。任何 API Key 都只应通过服务端环境变量配置；生成题目或启用模型后，相应输入与对话内容会发送给你所选择的模型服务商处理。
