# 群面实验室 GroupLab

> 与三名不同风格的 AI 候选人完成一场无领导小组讨论，并获得基于团队状态变化的影响力报告。

普通模拟面试通常只评价“你答得怎么样”。群面实验室关注另一个问题：**你的发言有没有让团队向前走？**

当前版本提供一个无需 API Key 即可完整演示的确定性 MVP。用户可以参与真实的群面案例、提出标准、质疑方案、整合分歧、控制时间，并在结束后看到自己的发言如何改变团队共识。

## 当前核心闭环

1. 阅读群面案例与五个候选方案。
2. 与三名固定行为风格的 AI 候选人讨论。
3. 群体状态机识别用户的协作动作。
4. 共享面板实时更新评价标准、候选方案、核心冲突和共识度。
5. 用户代表小组完成最终陈述。
6. 系统生成五维评分、团队影响力时间线和下一轮唯一训练目标。

## 为什么不是三个自由聊天 Agent

三个完全独立的 Agent 很容易重复发言、忘记案例事实或无法稳定地产生冲突。当前版本使用一个统一的“群面导演”状态机：

- 案例事实保持固定；
- 每轮只选择最应该回应的 1-2 名候选人；
- 候选人风格稳定但会根据用户行为调整立场；
- 每条评价都必须对应一次可见的对话或团队状态变化；
- 无 API Key 时也可以稳定复现完整 Demo。

## 评分维度

| 维度 | 分值 | 观察内容 |
| --- | ---: | --- |
| 有效贡献 | 25 | 是否提出新信息、判断标准或明确方案 |
| 推动进展 | 25 | 是否帮助团队从发散走向结论 |
| 倾听整合 | 20 | 是否回应并吸收他人的有效观点 |
| 冲突处理 | 15 | 是否让分歧产生信息，而不是变成人际对抗 |
| 结构节奏 | 15 | 是否建立标准、控制时间并清楚总结 |

## 当前取舍

刻意没有加入：

- 语音、视频和数字人；
- 登录、简历和题库广场；
- 多场景管理；
- 三个相互独立且不可控的 Agent；
- 只根据发言次数生成的笼统评分。

第一阶段优先验证一个问题：学生是否能从“团队状态变化”反馈中获得比普通聊天式模拟更有价值的群面训练。

## 下一步

## 隐私

当前案例不要求上传简历或真实个人信息。测试和演示请继续使用假名与脱敏数据，任何 API Key 都只应通过服务端环境变量配置。
